## 基本流程

1. 一方手牌出完，服务端判定本局结束并下发 `settle` 事件。
2. 客户端停止所有进行中的倒计时与操作响应，桌面定格。
3. 结算浮层以缩放淡入方式出现（300ms，`Back.easeOut`）。
    1. 顶部为本局结果标题——本家获胜显示「胜 利」，失败显示「失 败」。
    2. 标题下方为本局倍数的构成链条，横向排列：底分 → 叫分 → 加倍 → 炸弹 → 春天。
    3. 中部为本家赢豆结果，正数显示 `+1200`（绿色，前置 `+`），负数显示 `-1200`（红色，前置 `-`）。
    4. 下部为三家明细列表，逐行显示头像、昵称、身份、本局输赢豆子。
    5. 底部为两个按钮——主按钮「再来一局」、次按钮「返回大厅」。
4. 结算金额以滚动累加动画呈现（600ms，从 0 滚到最终值），同时播放胜负音效。
5. 若本局出现春天或反春，标题下方追加「春天 ×2」或「反春 ×2」标签。
6. 若本局出现炸弹，倍数链条中炸弹节点显示为金色并带脉冲动画。
7. 用户点击「再来一局」。
    1. 浮层收起，服务端重置房间。
    2. 返回等待态，重新发牌，进入下一局。
8. 用户点击「返回大厅」。
    1. 断开长连接，返回游戏大厅页。
    2. 大厅刷新欢乐豆余额。

## 异常情况

1. 结算数据异常：
    1. `settle` 事件缺少 `delta` 字段，本家金额显示为 `--`，其余明细照常展示。
    2. 结算下发的三家金额之和不为 0（服务端计算错误），前端仍按原值展示，同时上报日志并禁止点击「再来一局」。
2. 资金异常：
    1. 结算后欢乐豆为负数，显示实际负值并提示「欢乐豆不足，请前往新手场」。
    2. 欢乐豆为 0 且进入负值场次，提示后自动跳转新手场。
3. 网络异常：
    1. 点击「再来一局」时断网，提示「网络异常，请检查网络」，浮层保持。
    2. 点击「返回大厅」时断网，仍执行本地跳转，仅余额不刷新。
4. 超时异常：
    1. 结算浮层停留超过 30 秒未操作，自动执行「再来一局」。
    2. 自动执行时若服务端已解散房间，则跳转大厅并提示「房间已解散」。
5. 重复结算：
    1. 收到重复 `settle` 事件时，以第一条为准，后续忽略。
    2. 浮层已展示时再次收到结算，不重复播放动画与音效。

## 业务规则

1. **结算权威**：所有金额、倍数、春天标记一律以服务端下发为准，客户端不得自行计算。
2. **结算公式**：`单方结算额 = 底分 × 倍数`；地主与两名农民对局，地主结算额为单方结算额的 2 倍，两名农民各为 1 倍。即地主赢时 `地主 +2×底分×倍数`、两农民各 `−底分×倍数`；地主输时反向。三家金额之和恒为 0。
3. **倍数链条**：展示顺序固定为 底分 → 叫分倍数 → 抢地主倍数 → 加倍倍数 → 炸弹计数 → 春天/反春系数。
4. **金额颜色**：赢为正数显示绿色 `#43A047`，输为负数显示红色 `#E53935`。绿色代表收入、红色代表支出，按游戏结算惯例，不沿用股市红涨绿跌。原版具体色值待截图核对（00 册 N-01）。
5. **春天判定**：地主先出且农民全程未出过一张牌；反春为农民仅让地主出过一手即走完。
6. **炸弹计数**：只统计**有效炸弹**（接他人牌时打出），主动出炸弹不计入，与 00 册 4.5 空炸规则一致。
7. **再来一局**：同一房间内连局，保留场次与座位，不重新匹配。
8. **返回大厅**：释放座位，房间可被其他玩家加入。
9. **结算不阻断**：结算浮层展示期间，牌桌不再响应任何牌面操作。
10. **战绩落库**：每局结束写入战绩记录，字段含时间、场次、身份、结果、输赢豆子、倍数。

## 编码要求

### 用户页面要求

1. 结算浮层必须使用 Phaser 容器绘制，与牌桌同一渲染层，不得改成 DOM 浮层（避免层级错乱）。
2. 视觉必须对齐基线册第 5 章：深色底、金色描边、金额红绿区分。
3. 金额滚动动画时长 600ms，胜负音效与动画同时起播。
4. 浮层出现时牌桌必须整体压暗（0.55 遮罩），但不得停止渲染。
5. 结算数据必须完全来自服务端 `settle` 事件，前端不得做任何金额推导。

### 编码规范基线

1. 遵循 uni-app 编码规范：样式单行、选择器间无空行。
2. 结算渲染独立为 `renderSettle()` 方法，不得与 `renderState()` 混写。
3. 音效通过 `DdzAudio.win()` / `lose()` 调用，不新建音频实例。
4. 金额格式化统一走工具函数，不散落在渲染代码中。
5. 所有方法写 JSDoc：用途、参数、返回值。
6. 浮层对象生命周期必须显式管理（创建后存入成员变量，销毁时统一 `destroy()`）。

## 页面组件清单与职责划分

| 实体 | major/minor | 关键字段（语义） | 接口字段名 |
| --- | --- | --- | --- |
| 结算结果 | 【待补充】 | 胜方座位、本家输赢、底分、总倍数、倍数构成、春天标记、炸弹数 | `winner` / `delta` / `baseScore` / `multiple` / `chain` / `spring` / `bombCount` |
| 结算明细 | 【待补充】 | 座位、昵称、身份、输赢豆子 | `seat` / `nickname` / `role` / `delta` |
| 战绩记录 | 【待补充】 | 用户、时间、场次、身份、结果、输赢、倍数 | `userId` / `time` / `roomName` / `role` / `result` / `delta` / `multiple` |

> 三张表均为本期新增，`major/minor` 待数据库设计阶段确认。

| 当前态 | 触发 | 条件 | 下一态 | 副作用 |
| --- | --- | --- | --- | --- |
| 对局中 | 收到 `settle` | 首次 | 结算展示 | 停止倒计时，压暗牌桌，播放动画与音效 |
| 结算展示 | 收到重复 `settle` | 非首次 | 结算展示 | 忽略，不重复播放 |
| 结算展示 | 点击「再来一局」 | 网络正常 | 等待重发 | 收起浮层，重置房间，重新发牌 |
| 结算展示 | 点击「返回大厅」 | — | 已离开 | 断连，跳转大厅，刷新余额 |

2. `chain` 缺失时仅展示总倍数，不展示构成。
3. `spring` 为 `0/1/2` 分别表示无春天、春天、反春。
